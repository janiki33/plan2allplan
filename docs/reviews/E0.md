### MAJOR-4 – `2>&1` zusammen mit `$ErrorActionPreference = 'Stop'` (PowerShell 5.1)

`:53` setzt `$ErrorActionPreference = 'Stop'`, `:95` ruft `$output = & git -C $RepoRoot @Arguments 2>&1` auf.
In Windows PowerShell 5.1 werden stderr-Zeilen eines nativen Kommandos durch `2>&1` in `ErrorRecord`-Objekte
umgewandelt; bei `ErrorActionPreference = 'Stop'` löst die erste solche Zeile einen terminierenden
`NativeCommandError` aus – noch bevor `$LASTEXITCODE` in `:97` geprüft wird. `git pull` und `git push`
schreiben ihren Fortschritt (`From github.com:…`, `To …`, `Everything up-to-date`) routinemässig nach stderr.
Das Skript bricht also voraussichtlich bereits in Schritt 1 des Protokolls mit einer roten Fehlerzeile ab,
obwohl git erfolgreich war. Übliche Abhilfe: innerhalb `Invoke-Git` lokal
`$ErrorActionPreference = 'Continue'` setzen (oder `$PSNativeCommandUseErrorActionPreference` in PS 7 /
`cmd /c … 2>&1` in 5.1) und weiterhin nur über `$LASTEXITCODE` entscheiden.

durch den Auftraggeber nicht sinnvoll durchführbar – man würde ihn in einen Testlauf schicken,
der planmässig scheitert.
